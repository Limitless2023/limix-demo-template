# lib/limix/
> L2 | 父级: ../../AGENTS.md

LimiX 开放平台的服务端调用层。全部文件带 `server-only`：API Key 只在服务端，浏览器只调本站 `/api/*`。

- `config.ts`: 环境变量（地址、Key、模型规格）与模拟模式判定。没配 Key 或 `LIMIX_MOCK=1` 时走模拟，页面必须标明「模拟结果」。
- `client.ts`: HTTP 层，唯一直接请求 LimiX 的文件。上传、时序同步预测、异步任务提交与轮询（`waitForTask`）、下载。成功响应 `code: 0`，否则抛 `LimixError`（带原始错误码）。轮询节奏是实测结论（先等 4 秒、之后每 3 秒），改之前先读函数注释。所有请求经 `send()`，用 undici 自己的 fetch 与连接池（全局 fetch 不能单独设连接超时）：连接超时 5 秒、连接层失败重试 1 次，连不上约 10 秒报错。LimiX 服务器会对部分境外云服务器出口 IP 直接丢包（2026-10-16 查明，同一时刻香港三个出口 IP 一个通两个不通），分到这类 IP 时重试也没用，只能尽快报错，根治在平台侧。
- `forecast.ts`: 时序预测链路：样例按路径缓存在 globalThis；按预测日切出历史（contextSize 行）与未来点位（带已知输入、回测时带实测），或从上传的表里按「目标列为空的尾部行」切；上传历史（与未来点位）→ 异步时序任务（`col_covariates` 传已知输入，P10 / P50 / P90）→ 取回。目标值有公布延迟的对象（`gapDays`）历史只用到延迟之前，间隔的几天一起预测、结果里丢掉。已知输入的空值先前向、再后向补。模拟模式按近 7 天同一时刻均值外推。
- `instant.ts`: 即时预估链路（`getContextCsv` 导出当前上下文供下载，`getContextFile` 给留痕用的上下文版本：内容、指纹、数据版本、来源与变更）：上下文按「场景 + 操作人」缓存在 `globalThis`（开发热更新与多路由共用；初始行按场景共用），只上传一次；`gen` 计数防止上传途中上下文变化后误用旧版本。预测按步骤回调耗时，新记录不带目标列与 ID 列（LimiX 会把 ID 当特征）。场景配置写了 `model`（如烘干用 LIMIX_64M）就按它提交，否则用环境变量的规格。模拟模式用上下文表 7 近邻。

依赖方向：`app/api/*` → `forecast.ts` / `instant.ts` → `client.ts` → `config.ts`。业务代码不直接 `fetch` LimiX。
